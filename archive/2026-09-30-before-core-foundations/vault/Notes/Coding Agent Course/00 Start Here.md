## How to study

Attempt the question, inspect the selected source, then explain the result in your own words. Expand the next exercise around demonstrated understanding. Material availability, tool installation and a passing date do not establish learning completion.

Record the date, focused minutes, explanation, code/output link and remaining question in the owning project's progress log. Keep personal annotations beside the relevant reading; preserve them when revising material. Project tasks have no duplicate checklist here.

Use an existing harness on small real tasks while learning to build and extend agents. Reuse the same task runner and agent across JavaScript/Node, TypeScript, Pi, worker and Linux projects rather than starting unrelated implementations.

## Scope and capacity

The shared study budget is **15 focused hours/week**: normally 10 core study/labs, 3 project work and 2 exploration. Assessments, terminal practice and supporting readings count inside that total. Every execution project must fit within three weeks; the course itself can span longer. At each checkpoint, inspect actual effort and remaining scope, split oversized work, and update dates only in the owning projects.

The terminal pilot practices human direction, review and session continuity. The GUI project examines follow-up, review and reconnect through an interface. The team capstone reuses reliable worker and Linux foundations to test coordinator-led work with final human review. A particular GUI or a larger agent count is not itself a completion requirement.
